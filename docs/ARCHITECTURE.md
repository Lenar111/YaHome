# Архитектура

## Общая картина

```
┌────────────────────────────┐        HTTPS (Bearer OAuth)
│ Яндекс IoT API v1.0        │◄──────────────────────────────┐
│ api.iot.yandex.net         │                               │
└────────────────────────────┘                               │
                                                  ┌──────────┴─────────┐
 Keychain ──токен──────────────────────────────►  │  HomeModel         │  ObservableObject
 UserDefaults ──избранное, порядок, строка меню─►  │  (состояние, API,  │
 history.json ◄──► история датчиков ────────────►  │  опрос, история)   │
                                                  └───┬────────────┬───┘
                                                      │            │
                                    SwiftUI-вид (RootView)    AppDelegate
                          плитки · детали · сценарии ·        NSStatusItem + NSPopover
                          статистика · настройки              (значок и числа в строке меню)
```

Приложение — **агент** (`LSUIElement`): без значка в Dock. Окно — `NSPopover` с `NSHostingController(rootView: RootView)`.

## Почему один файл
Установщик (`.command`) содержит исходники внутри и компилирует их у пользователя командой `swiftc`. Файл с кодом верхнего
уровня должен быть единственным, поэтому проект — один `YaHome.swift` (+ необязательный `Icons.swift`, который
склеивается с ним при сборке: `tools/build.sh`, `tools/make_installer.py`). Плюсы: нет Xcode-проекта, подписи
разработчика и бинарников в репозитории; минусы — длинный файл (разбит на блоки `// MARK: -`).

## Блоки `YaHome.swift`

| Блок | Назначение |
|---|---|
| `Keychain` | хранение токена в связке ключей (`SecItem*`), служба `local.yahome.menubar` |
| `AuthServer` | локальный приёмник на `127.0.0.1:8765` для OAuth-перенаправления (`NWListener`, только loopback) |
| Модели (`Dev`, `Room`, `Household`, `Scen`, `RangeCap`, `ModeCap`, `ToggleCap`, `ColorCap`, `Prop`) | разбор JSON `/user/info`, вычисляемые свойства устройства: категория, значок, строка статуса |
| `HomeModel` | единственная «модель вида»: токен, комнаты, сценарии, опрос, команды, избранное, настройки, история и окно статистики |
| Плитка и детали (`Tile`, `DetailView`, `QuickPanel`, `DeviceControls`, `ColorControl`, `RangeControl` …) | интерфейс управления |
| Статистика (`StatsPage`, `StatsNav`, `StatsPicker`, `StatCard`, `LineChart`) | графики, навигация, календарь |
| `SettingsView` | настройки: строка меню, порядок, вход/выход |
| `AppDelegate` | значок в строке меню, открытие по наведению, отрисовка чисел в строке меню |

## Данные и API

Используются три вызова публичного API Яндекса (`https://api.iot.yandex.net/v1.0`):

| Метод | Путь | Зачем |
|---|---|---|
| GET | `/user/info` | дома, комнаты, устройства, их возможности (capabilities) и свойства (properties), сценарии |
| GET | `/devices/{id}` | быстрое обновление одного устройства (во время нагрева, при управлении) |
| POST | `/devices/actions` | команды: вкл/выкл, диапазоны (яркость, температура), режимы, цвет, сцены |
| POST | `/scenarios/{id}/actions` | запуск сценария Алисы |

**Опрос.** Окно открыто — полное обновление раз в 15 с, закрыто — раз в 60 с. Если есть «занятое» устройство
(чайник, процесс) — точечное обновление каждые 1,5–3 с. Это держит нагрузку на API небольшой и одновременно даёт
живой прогресс нагрева.

**Оптимистичное обновление.** После команды (`hold`) значение сразу меняется на экране и «удерживается» 8 секунд:
устаревшие ответы опроса за это время не откатывают плитку назад, пока устройство не подтвердит новое состояние.

**Ошибки.** Коды ошибок API (`DEVICE_UNREACHABLE`, `DEVICE_BUSY`, `REMOTE_CONTROL_DISABLED`, …) превращаются в понятные
сообщения (`errText`).

**Ярлык «не отвечает».** Если производитель не выполнил команду, устройство получает отметку на 10 минут.

## Устройство → категория, значок, картинка
Подробно — [DEVICES.md](DEVICES.md). Коротко: `Dev.kind` (тип Яндекса без префикса `devices.types.`) → `Dev.cat` (категория
для фильтров) и `Dev.symbol` (первый доступный значок SF Symbols из списка кандидатов). Для устройств с типом `other`
используются слова из названия. Если есть растровая картинка (`Icons.iconData`), показывается она; иначе рисуется
векторная «карточка» в цвете категории.

## Строка меню
`AppDelegate.render()` собирает `NSImage`, а не `NSStatusItem.title`: так можно в одной картинке смешать значки и
числа, задать моноширинные цифры и цвет отдельным числам. Если цветных чисел нет, картинка остаётся *template*
(система сама красит её под светлую/тёмную строку меню); если есть — рисуется с цветом, нейтральные части
подбираются по `effectiveAppearance` кнопки.

## Статистика
См. [STATISTICS.md](STATISTICS.md). Коротко: фоновая запись показаний → `history.json`, многоуровневое сжатие,
окно просмотра (`statsWindow`) вычисляется из периода и «якоря», график — `LineChart` на `Path` с ползунком на
`onContinuousHover` (macOS 13+).

## Принципы кода
- Без `@State`, `@Observable` и макросов: сборка обычным `swiftc` на любой машине с Command Line Tools.
- Все привязки — `Binding(get:set:)`; все долгоживущие объекты — классы с `@Published`.
- Нет сторонних зависимостей.
- Для тяжёлых форматтеров (даты) — кэш по формату (`dfmt`).
