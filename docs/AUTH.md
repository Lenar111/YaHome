# Вход и токен

## Как это работает
1. По кнопке «Войти через Яндекс» открывается `https://oauth.yandex.ru/authorize?response_type=token&client_id=…&redirect_uri=http://127.0.0.1:8765/callback`.
2. Приложение на время входа (до 10 минут) слушает **только** `127.0.0.1:8765` (`NWListener` с `requiredInterfaceType = .loopback`).
3. Яндекс возвращает пользователя на `http://127.0.0.1:8765/callback#access_token=…`. Токен в *фрагменте* адреса (после `#`) на сервер
   не уходит, поэтому страница-приёмник маленьким скриптом пересылает его приложению на `/t?…`.
4. Токен кладётся в связку ключей (`Keychain.set`). После этого приёмник закрывается.

Вариант «без браузера»: вставьте свой OAuth-токен в поле входа.

## Права (scope)
Приложению нужен доступ к умному дому: чтение состояния и управление устройствами. Права задаются при регистрации OAuth-приложения на oauth.yandex.ru.

## Свой ID приложения
В коде зашит `clientID` — это публичный идентификатор OAuth-приложения, не секрет. Но если вы публикуете форк или
хотите независимость от чужой регистрации, зарегистрируйте собственное приложение на https://oauth.yandex.ru
(платформа «Веб-сервисы»), укажите Callback URI `http://127.0.0.1:8765/callback`, отметьте права на умный дом и
подставьте свой ID в `let clientID = "…"` (начало `Sources/YaHome.swift`).

Без пересборки (для установленного приложения):
```bash
defaults write local.yahome.menubar clientID "ВАШ_ID"      # вернуть по умолчанию: defaults delete local.yahome.menubar clientID
```

## Хранение и отзыв
- Токен — только в связке ключей (служба `local.yahome.menubar`, учётная запись `token`).
- Выход в настройках удаляет его. Деинсталлятор тоже (`security delete-generic-password`).
- Отозвать доступ целиком можно в настройках безопасности аккаунта Яндекса (разделы со списком приложений).
- Код подписывается *ad-hoc* с фиксированным идентификатором, поэтому после обновления macOS не просит пароль к ключу заново.
